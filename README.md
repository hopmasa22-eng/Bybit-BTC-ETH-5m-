# Telegram-бот сигналів MEXC Futures — свічки 5 хвилин

Бот використовує нативні свічки 5 хвилин із публічного MEXC Contract API (`interval=Min5`). Символи `BTCUSDT` і `ETHUSDT` запитуються як лінійні USDT-контракти. Свічки завантажуються з MEXC Contract API.

## Налаштування Railway

Додайте `TELEGRAM_BOT_TOKEN` і `TELEGRAM_CHAT_ID` у Variables. Необов’язкові змінні: `MEXC_SYMBOLS=BTCUSDT,ETHUSDT` (назва збережена для сумісності зі старим деплоєм), `POLL_SECONDS=15`, `TEST_MODE=true` для локальної перевірки конфігурації.

## Правила

- Загальна основа: свічки №1–3 одного кольору; №1 має бути першою свічкою цього кольорового відрізка; №4 — протилежного кольору; №5–6 будь-які.
- Правило 1: №7 має бути кольору №1; після закриття №8 надсилається попередження; після закриття №9 сигнал надсилається лише якщо №9 протилежна кольору №1. Результат перевіряється на №10–15: хоча б одна свічка кольору №1 = WIN; усі шість протилежного кольору = LOSS.
- Правило 2: на початку формування №7 надсилається попередження, якщо поточний колір №7 протилежний кольору №1; після закриття №7 сигнал надсилається, лише якщо колір залишився протилежним. Результат перевіряється на №8–14: хоча б одна свічка кольору №1 = WIN; усі сім протилежного кольору = LOSS.
- Для SHORT правила дзеркальні до LONG. DOJI не вважається зеленою або червоною свічкою і не дає автоматично оголосити LOSS.

## UTF-8

`main.py` збережений у UTF-8; повідомлення Telegram надсилаються через JSON (`requests` параметр `json=`), а файли стану читаються/записуються з `encoding="utf-8"` та `ensure_ascii=False`.

## Розгортання

Розпакуйте архів і завантажте файли в проєкт Railway. Після запуску перевірте журнали на `MEXC` і `НОВІ ДАНІ`. Бот надсилає повідомлення, але не відкриває угоди. Для збереження стану між перезапусками потрібне постійне сховище або інше постійне зберігання state-файлів.
